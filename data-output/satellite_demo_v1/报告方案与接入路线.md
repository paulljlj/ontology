# 卫星分析报告：要增加什么、如何接入

> 早期设计存档，不是当前进度。实际状态见根目录[HANDOFF.md](../../HANDOFF.md)：旧版已备份推送，我们已完成路径、本体、执行、真实MCP和页面；B的诊断仍待接入。本文参考改路的可用度提升来自生成器设置，现有路径代码不预测改路后可用度。

## 目标

沿用截图的异常概况、共同依赖和反向检查。再回答：哪里异常，为什么可能异常，哪些对象还没达到重大告警阈值但需要关注，以及有没有满足容量与时延要求的备选路径。

这里的“可用度”是网络服务成功率。不能把服务下降直接说成某颗卫星硬件损坏，也不能把候选评分当成真实故障概率。

## 报告分成六部分

| 部分 | 具体回答 | 主要数据依据 |
| --- | --- | --- |
| 异常概况 | 哪些业务下降、下降多少、持续多久、影响多少条路由 | service_metrics、services |
| 根因候选与异常原因 | 优先排查哪个对象；可能是过载、链路质量还是设备错误；支持和反对证据是什么 | routes、route_hops、node_metrics、link_metrics、events |
| 潜在或轻微异常 | 哪些业务下降未超过5个百分点，但已经持续变差；是否伴随高负载或错误 | service_metrics、节点和链路负载、告警 |
| 备选通信路径 | 原来怎么走、建议怎么走；同时迁移后是否有余量、时延是否达标 | links、traffic、services、当前路由与资源状态 |
| 影响与对照 | 共用这个对象但没有下降的业务有哪些；同站不同中继是否正常；还有哪些风险没解决 | 全量业务及当时有效路由，不能只看已告警对象 |
| 结论与待补证据 | 先查谁、先做什么、还缺什么；证据不足或没有可行改路时明确说明 | 每项结论对应的样本ID、事件ID和时间 |

“原因”要写出机制。例如“SAT-20的到达流量超过转发容量，发生丢弃”比“多条路由都经过SAT-20，所以SAT-20坏了”多了可核查的数据依据。

## 用本次主案例讲清楚

以下仅为生成数据的说明和参考试验，不是现有系统已经生成的诊断报告。

1. 明显异常：SAT-03对应的SVC-001，正常基线约99.49%，10:00至10:15平均约92.45%，下降7.04个百分点。共有10条业务触发重大异常。
2. 对照关系：这10条业务经过SAT-20，但到达不同地面站。同一地面站下、经其他中继的正常业务可用来比较，不能仅凭“共用地面站”就认定站点故障。
3. 机制线索：10:10附近SAT-20到达流量约1075 Mbps，额定转发容量1000 Mbps；同时存在丢弃和队列告警。这支持“中继过载”的解释，但报告仍应标为待核查的原因判断。
4. 轻微异常：SAT-06对应的SVC-015同期下降约2.27个百分点，未超过5个百分点，但持续下降且路径资源负载偏高，应列入关注清单。不能因未触发重大告警就忽略，也不能宣称它一定会故障。
5. 改路参考：将上述10条业务一起由SAT-20迁到SAT-21。SAT-21请求利用率约82.19%，满足演示中不超过85%的要求。SVC-001的参考路径由SAT-03→SAT-20→GS-01改为SAT-03→SAT-21→GS-01。
6. 结果边界：在10:10同一需求下，SVC-001模型估算可用度由92.41%提高至99.37%。这是模拟估算，不是实际切换效果；原有SAT-24轻微下降也没有被这次改路解决。

CASE-005专门保留缓慢变化：10:15时可能还没攒够连续10点的关注证据，后续才满足条件。不能把后面的持续下降提前写进首轮报告。

## 与现有系统怎么接

现有数据报告流程继续保留。新增卫星流程，不把卫星代码全部塞进经营数据分析处理器。

```text
用户选择案例、时段与分析要求
        ↓
生成 task_plan：读取 → 检测 → 找候选 → 比较证据 → 验算备选路径 → 报告
        ↓
每一步保存 task_key、skill_spec、输入及输出
        ↓
执行器查注册表，调用对应的真实 Python 处理函数
        ↓
产生结构化 satellite_report，再由前端展示与下载
```

| 新增部分 | 做什么 |
| --- | --- |
| 文件数据适配器 | 读取CSV，按案例、时段、证据可获得时间联接；校验缺失和标识 |
| 卫星领域本体 | 定义卫星、地面站、链路、路由、业务、指标观测和告警，以及业务使用路由、路由经过节点/链路、观测属于对象等关系 |
| 本体关系查询 | 找异常业务的共同依赖及相关正常对照；使用当时生效的关系，不能拿切换后的路径解释切换前 |
| 新的处理能力 | 检测明显和轻微下降、比较原因证据、计算和验算备选路径、生成报告 |
| 可调用能力注册表 | task_key标识业务步骤，skill_spec声明处理器及参数；注册表把声明解析为允许执行的函数，不执行任意生成代码 |
| 报告展示 | 展示六部分内容，结论可点开查看指标、路由和告警；缺证时保留不确定性 |

阈值和容量计算由Python完成，本体负责对象及关系约束。大模型可帮助解析要求和组织文字，但不能凭提示词编造指标、根因或改路收益。首版采用简单候选路径生成和约束校验即可，不需要先训练复杂模型。
