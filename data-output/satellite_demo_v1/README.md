# 卫星网络分析模拟数据集 v1

> 本文件说明数据，不证明诊断系统已经实现或准确。当前实现、分工与运行方法见根目录[HANDOFF.md](../../HANDOFF.md)。文末“下一步”及相邻接入路线保留早期设计语境；我们现在已完成路径/系统/MCP，B的诊断仍待接入。

- 42颗卫星、3个地面站、126条有向链路。
- 8个独立案例，每个案例18条端到端业务。
- 时间：北京时间采样区间[2026-09-15 09:30,11:31)，最后一个timestamp为11:30，每分钟一个样本，共121点。
- 基线09:30至10:00；首轮分析10:00至10:15；初诊证据截止10:16。末端时间均不包含。
- 11个CSV文件，共201,206行数据。

## 指标口径

“可用度”指从源卫星到固定目标地面站的端到端服务成功率，等于成功探测数/总探测数×100，不表示卫星硬件健康度，也不是AI判断的可信度。99%降到92%是下降7个百分点。

演示重大异常：相对该业务正常基线下降严格大于5个百分点，连续3个有效采样点。关注对象：下降1至5个百分点且持续10点，并伴随高负载或设备错误。规则可配置，不是行业标准；持续关注也不等于必然发生故障。计划切换单独标记，不能删除原始异常记录。

## 如何防止“看答案做分析”

诊断只能读取manifest.json中的diagnosis_allowlist。案例编号和输入表不写预设根因。evaluation目录、生成器内部配置不得被检索进提示词或诊断上下文。初诊按available_at过滤；故障后的维护、恢复不能用于事先判断。事件结束信息应由状态更新发布，不能让首个告警提前知道未来恢复时间。

## 数据生成模型与限制

固定种子20260915，所有案例可重现。业务流量依次经过源节点、源星到中继链路、中继节点、中继到地面站链路和地面站。每个资源先汇总真实到达的流量，再按容量等比例分配，扣除模拟设备/传输损失；下游只收到上游实际转发量。请求利用率可大于100%，实际转发不超过容量。节点负载按Mbps计算，不用“路由条数多”替代容量判断。

探测可用度由路径交付比例、正常探测基线和计划切换过渡共同产生；丢包率与服务探测失败率不是同一指标。队列、温度、CPU与SNR是可解释的简化代理模型，未进行真实轨道、无线调制、跨分钟队列或空间环境物理仿真。未承载这18条业务的节点流量为0，不能据此推断现实全网没有其他业务。

辐射相关场景分别提供虚构环境计数、存储错误和重启；另有环境计数高但业务正常的对照。NASA说明空间辐射可能造成电子器件单粒子效应，但本数据的计数、阈值和事件关系均为演示设定，不可套用到真实卫星：[NASA空间辐射与航天器电子器件介绍](https://science.nasa.gov/science-research/heliophysics/how-nasa-prepares-spacecraft-for-the-harsh-radiation-of-space/)。

## 备选路径怎么用

先按当时可用的有向链路生成候选路径，保持源和允许的地面站出口不变，再同时放入全部待迁移业务，检查节点、链路利用率不超过85%及业务时延不超过150ms。不能只单独检查每条路径。链路可见窗口是模拟接触计划，非星历计算。

参考试验保存在evaluation/reroute_reference.json：它是同一需求下的模拟前后对照，不是实际切换测量，也不是已经上线的路由优化算法。没有满足约束的路径时必须明确报告“暂无可行路径”。

## 接入现有系统的下一步

1. 先保存当前系统版本，再增加卫星数据文件适配器，按case_id和时间读取这些表。
2. 建模Satellite、GroundStation、CommunicationLink、Route、NetworkService、MetricObservation和AlarmEvent等对象，并导入带时间的路由关系。
3. 增加读取校验、异常/关注检测、共同依赖、证据比较、备选路径校验和报告生成处理器。
4. 通过现有task_plan、task_key、执行记录和报告下载串起来；执行器按注册表调用真实处理函数。
5. 用独立答案检验规则是否有效，再接真实数据。不能用本数据生成的表现承诺真实准确率。
