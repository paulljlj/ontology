## 1. 合并后的职责边界

同学模块现在位于 `backend/satellite_diagnosis/`，继续负责：异常概况、根因候选与原因、轻微异常、影响与正常对照、结论及缺失证据。我们的原模块继续负责：OWL对象与关系约束、任务编排、证据二次核验、备选路径联合容量/时延验算、API、前端和下载。

一次自动运行变为：

```text
读取时点观测
  → 校验本体对象/关系
  → 同学诊断：阈值检测 + 时态路由共同依赖 + 容量/环境/告警 + 正常对照
  → 适配并核验 DiagnosisInput（只保留可追溯摘要）
  → 采用优先 supported 候选验算备选路径
  → 合并六部分报告
  → 生成主 JSON、HTML、完整诊断审计 JSON
  → 校验文件与哈希
```

对应 `task_key` 为：`load_snapshot → validate_domain → diagnose_network → plan_routes → build_report → publish_report → verify_delivery`。如果用户关闭自动诊断并手动输入待避对象，仍保留原来的六步流程；粘贴外部契约 JSON 时使用 `accept_diagnosis`。

## 2. 为什么需要适配器

同学原始报告是 schema 1.1，包含逐分钟诊断过程，CASE-001 约 3.7 MB；现有系统接收的是稳定的 `DiagnosisInput 1.0`。`backend/app/application/satellite_diagnosis_adapter.py` 做以下转换：

- 把通用 `node` 候选按资产表映射为 `satellite` 或 `ground_station`，链路保持 `link`。
- 对指标/事件证据按来源、记录、对象、字段和时间去重，生成稳定 `evidence_id`。
- 只接收 `observed/*.csv` 中能在本次案例、快照、`available_at` 截止时间内重新核对的证据。
- 只有同学报告的第一优先对象同时具备 `multi_signal` 证据时标记 `supported`；其他对象保留为 `candidate`，避免把轻微风险一起强制改路。
- 将轻微异常、正常对照和数据质量压缩为前端摘要；完整分钟级结构单独保存，不塞进数据库运行请求。

系统不会执行诊断 JSON 里的代码、SQL、命令或路径。候选的 `supported` 表示当前数据支持优先核查，不代表已证明严格因果或硬件故障。

## 3. 运行方式

本地时态图模式不需要 Neo4j，适合当前演示：

```powershell
python backend/scripts/satellite_workflow_demo.py --case CASE-001
```

手动关闭自动诊断或覆盖待避对象：

```powershell
python backend/scripts/satellite_workflow_demo.py --case CASE-001 --no-auto-diagnosis --avoid SAT-20
python backend/scripts/satellite_workflow_demo.py --case CASE-001 --avoid SAT-20
```

Neo4j MCP 是可选真实开源关系查询后端。准备方式见 `backend/mcp/neo4j/README.md`；完成数据库、图导入、官方 v1.6.0 Server 和环境变量后，可运行：

```powershell
python backend/scripts/satellite_workflow_demo.py --case CASE-001 --diagnosis-backend neo4j_mcp
```

MCP 模式失败会让诊断任务失败，不会静默回退到本地图。默认本地图会在报告中写 `local_test_only`，前端也明确显示其不是 MCP 调用。
