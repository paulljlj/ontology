# 本体智能体工作台：使用与启动说明

本文说明如何在一台新的 Windows 电脑上获取、安装并启动本项目，以及如何使用本体智能体完成“输入需求 → 任务拆解 → 推理执行 → 结果交付”的完整流程。

## 1. 运行方式说明

本项目由两个服务组成：

- 前端：React + Vite，默认地址为 `http://localhost:5173`。
- 后端：FastAPI，默认地址为 `http://localhost:8000`。

`localhost` 始终表示当前电脑。因此，在另一台电脑使用本项目时，需要在那台电脑重新拉取代码、安装依赖并启动服务。GitHub 保存源代码，不保存本机已经安装的 Python 环境、`node_modules` 或正在运行的进程。

## 2. 环境要求

推荐安装：

- Git
- Python 3.11 或 3.12
- Node.js 20 或更高版本（包含 npm）
- 可选：Docker Desktop，用于运行 PostgreSQL、Neo4j 和容器化后端

在 PowerShell 中检查环境：

```powershell
git --version
python --version
node --version
npm --version
```

不建议使用 Python 3.14 等尚未被依赖完整支持的新版本。

## 3. 获取或更新代码

首次使用：

```powershell
git clone https://github.com/paulljlj/ontology.git
Set-Location ontology
```

本地已经存在项目时：

```powershell
Set-Location <你的 ontology 项目目录>
git switch main
git pull origin main
```

## 4. 推荐启动方式：SQLite 本地预览

这是最简单的启动方式，不需要安装 PostgreSQL 或 Neo4j，适合功能体验和本地开发。

### 4.1 创建 Python 虚拟环境

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
```

如果电脑上有多个 Python，请把第一条命令中的 `python` 换成实际可用的 Python 3.11/3.12 路径。不要复制其他电脑上的绝对路径。

### 4.2 创建后端配置

在 `backend` 目录中新建 `.env` 文件，写入：

```dotenv
DATABASE_URL=sqlite+pysqlite:///./ontology_demo.db
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
LLM_PROVIDER=rule-based
FEISHU_EVENT_ENABLED=false
```

说明：

- SQLite 数据库文件会保存在 `backend/ontology_demo.db`。
- `rule-based` 模式不需要 API Key。
- 飞书事件默认关闭，不影响本地报表执行功能。
- `.env` 可能包含密钥，不要提交到 GitHub。

### 4.3 启动后端

打开一个 PowerShell，在项目根目录执行：

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动成功后可访问：

- 后端首页：`http://localhost:8000`
- 健康检查：`http://localhost:8000/api/health`
- API 文档：`http://localhost:8000/docs`

开发时需要自动重载，可以在启动命令末尾加上 `--reload`。

### 4.4 安装并启动前端

再打开一个 PowerShell，在项目根目录执行：

```powershell
Set-Location frontend
npm install
npm run dev
```

浏览器打开：

```text
http://localhost:5173
```

首次启动需要安装依赖；后续通常可以直接运行 `npm run dev`。

## 5. Docker 启动方式

如果已经安装并启动 Docker Desktop，可以运行完整的 PostgreSQL、Neo4j 和后端环境：

```powershell
docker compose up -d postgres neo4j backend
```

查看容器状态：

```powershell
docker compose ps
```

前端仍在本机启动：

```powershell
Set-Location frontend
npm install
npm run dev
```

停止 Docker 服务：

```powershell
docker compose down
```

若要保留数据库数据，不要删除 Docker volumes。

## 6. 页面使用方法

1. 打开 `http://localhost:5173`。
2. 在“输入执行需求”中用自然语言描述目标，例如：

   ```text
   分析最近三个月各区域、各产品的销售额和回款情况，自动清洗重复与缺失数据，生成经营分析报告，并说明完整执行路径和验证结果。
   ```

3. 点击“运行需求”。
4. 左侧执行流程会逐步展示 Task、动态 Skill、MCP 能力绑定、推理规则、进度和输出。
5. 右侧知识图谱同步展示本体节点与关系：

   - 主干类：Project、Feature、Spec、Plan、Task。
   - 语义类：Goal、AnalysisIntent、TimeScope、Dimension、MetricDefinition。
   - 能力类：SkillDefinition。
   - 产物类：Artifact、DeliveryBundle。
   - 验证类：Verification。
   - 灰色实线表示显式关系，橙色虚线表示推理机推导出的关系。

6. 点击图谱节点可在“推理机判断”区域查看当前节点、触发规则和推理结论。
7. 执行完成后点击“查看结果”，先查看系统对问题的直接回答、关键指标、图表和建议，再下载用户交付文件。

未配置外部数据连接器时，系统会使用可追溯的内置演示数据完成流程，不要求用户上传文件。

## 7. 结果交付

一次成功执行通常会生成以下面向用户的结果：

- Excel 经营分析报告
- 可视化 HTML 分析报告
- Markdown 管理摘要
- HTML 执行与验证报告

内部 CSV、JSON 或中间计算数据仅用于执行和追溯，不作为主要用户交付物。

## 8. 健康检查

可以在 PowerShell 中检查服务：

```powershell
Invoke-WebRequest http://127.0.0.1:5173/ -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8000/api/health -UseBasicParsing
```

两个请求都返回状态码 `200` 时，说明前后端已正常运行。

## 9. 停止服务

如果前后端在终端中运行，分别在对应终端按 `Ctrl+C`。

如果使用 Docker：

```powershell
docker compose down
```

## 10. 常见问题

### 浏览器无法打开 `localhost:5173`

确认前端终端仍在运行，并检查 Vite 是否显示了 `Local: http://localhost:5173/`。

### 页面打开但无法运行需求

确认后端健康检查 `http://localhost:8000/api/health` 返回：

```json
{"status":"ok"}
```

### Python 提示缺少模块

确认启动后端时使用的是安装过依赖的虚拟环境：

```powershell
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 端口被占用

查看端口占用：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 5173,8000
```

如果已经是本项目进程，可以直接复用；否则停止占用端口的程序，或修改前后端端口并同步更新 `VITE_API_BASE` 与 CORS 配置。

### 换电脑后为什么还要安装依赖

GitHub 默认不会保存 `.venv`、`node_modules`、数据库进程或正在运行的服务。每台新电脑首次使用时都需要安装一次依赖；代码更新通常只需要执行 `git pull`。

## 11. 更新到最新版本

停止正在运行的开发服务后，在项目根目录执行：

```powershell
git pull origin main
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
Set-Location frontend
npm install
```

然后按第 4 节重新启动前后端。
